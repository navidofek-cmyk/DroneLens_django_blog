CI workflow (.github/workflows/ci.yml)

Spouští se při každém push na main / develop a při Pull Requestech na main.

Job: Backend (🐍 Django Tests)

KrokAkce
1. CheckoutStáhne kód (actions/checkout@v4)
2. Setup UVNainstaluje UV package manager (astral-sh/setup-uv@v3)
3. Install depsuv sync --frozen — instaluje včetně dev závislostí (pytest, ruff, bandit)
4. Lintuv run ruff check . — kontrola stylu kódu
5. Security scanuv run bandit -r blog/ django_blog/ -ll — kontrola bezpečnostních problémů
6. Testsuv run python manage.py test blog --verbosity=2 — 93 testů
7. Migration checkpython manage.py migrate --check — ověří, že nejsou neaplikované migrace
PostgreSQL service container CI job spouští PostgreSQL jako service container (ne SQLite) — testy běží na stejné DB jako produkce, čímž se odhalí pg-specifické problémy.

Job: Frontend (⚛️ React Build)

KrokAkce
1. Checkout—
2. Node.js 22Cache npm podle package-lock.json
3. Installcd frontend && npm ci
4. Lintnpm run lint — ESLint s React rules
5. Buildnpm run build — Vite produkční build
6. Upload artifactReact dist/ uloží jako artifact (7 dní)

Job: Docker Build (🐳)

Spouští se pouze na main a závisí na úspěchu obou předchozích jobů.

KrokAkce
Docker BuildxNastaví multi-platform builder
GHCR loginPřihlásí se do GitHub Container Registry pomocí GITHUB_TOKEN
Backend imageBuild + push ghcr.io/org/repo/backend:latest a :sha
Frontend imageBuild + push ghcr.io/org/repo/frontend:latest (target: prod)

Oba buildy používají cache-from: type=gha — GitHub Actions cache zrychluje opakované buildy.

CD workflow (.github/workflows/cd.yml)

Deploy na produkci probíhá automaticky po úspěšném CI na main.

name: CD — Deploy to Production

on:
  workflow_run:
    workflows: ["CI — Test & Build"]
    types: [completed]
    branches: [main]

jobs:
  deploy:
    if: ${{ github.event.workflow_run.conclusion == 'success' }}
    runs-on: ubuntu-latest
    steps:

      - name: 🚀 Deploy via SSH
        uses: appleboy/ssh-action@v1
        with:
          host: ${{ secrets.SERVER_HOST }}
          username: ${{ secrets.SERVER_USER }}
          key: ${{ secrets.SERVER_SSH_KEY }}
          script: |
            cd /opt/django_blog
            docker compose -f docker-compose.prod.yml pull
            docker compose -f docker-compose.prod.yml up -d
            docker image prune -f

      - name: ❤️ Health check
        run: |
          sleep 10
          curl -f https://${{ secrets.SERVER_HOST }}/api/posts/ || exit 1

      - name: 💬 Slack notification
        uses: slackapi/slack-github-action@v1
        with:
          payload: |
            { "text": "✅ DroneLens deployed to production: ${{ github.sha }}" }
        env:
          SLACK_WEBHOOK_URL: ${{ secrets.SLACK_WEBHOOK_URL }}

Manuální deploy na VPS

  1. Příprava serveru 
    sudo apt update && sudo apt install -y docker.io docker-compose-plugin git
sudo systemctl enable --now docker
sudo usermod -aG docker $USER
  2. Klonování projektu 
    git clone https://github.com/your-org/django_blog.git /opt/django_blog
cd /opt/django_blog
cp .env.example .env
nano .env  # vyplňte produkční hodnoty
  3. Spuštění produkčního stacku 
    docker compose -f docker-compose.prod.yml up -d
docker compose -f docker-compose.prod.yml exec backend uv run python manage.py createsuperuser
  4. SSL certifikát (Let's Encrypt) 
    sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d your-domain.com
# Certifikát se automaticky obnoví přes cron
  5. Ověření běhu 
    curl https://your-domain.com/api/posts/
docker compose -f docker-compose.prod.yml ps
Produkční checklist Před prvním spuštěním v produkci: (1) nastavte silný DJANGO_SECRET_KEY, (2) nastavte DJANGO_DEBUG=False, (3) nastavte správné DJANGO_ALLOWED_HOSTS, (4) použijte HTTPS, (5) pravidelné zálohy PostgreSQL.
